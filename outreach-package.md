### 2.2 r/SaaS — Full Post (Technical Depth)

**Title**: How I engineered a zero-latency TanStack Start + Supabase AI stack with client-side BYOK encryption — full architecture breakdown

**Tags**: `[Technical]` `[Architecture]` `[Discussion]`

**Body**:

```
I've been building Signhify — an AI-native product studio where clients describe an idea and we ship the full SaaS in 2 weeks.

Here's the architecture that makes it work. Engineers might find the BYOK piece especially interesting.

---

**Stack overview**:

[Frontend] TanStack Start + React 19 → SSR with zero-client-js pages possible
[AI Gateway] Multi-provider router (Claude 3.5 Sonnet / GPT-4o / custom) with auto-fallback + circuit breaker
[Encryption] AES-256 GCM, client-side, user's own API key never touches our server
[Backend] Supabase PostgreSQL + RLS + Edge Functions
[Deploy] Cloudflare Workers (via Nitro)
[Billing] Stripe Checkout + webhook-driven metering

---

**The BYOK (Bring Your Own Key) architecture**:

This is the part most people ask about. How do you run AI on the user's API key without it touching your server?

1. User pastes their OpenAI/Anthropic key in our client-side vault
2. Key is encrypted with AES-256 GCM using a per-session derived key
3. Encrypted key stored in Supabase with RLS — only that user's session can decrypt
4. API calls are proxied through an edge function that decrypts in-memory, calls the provider, returns the response — key never written to logs or persisted unencrypted
5. User can revoke at any time. Key never stored on application server

This means zero liability for us and zero trust issues for clients — especially enterprises that require data isolation.

---

**Why TanStack Start over Next.js**:

I evaluated both and went with TanStack Start + React 19 for:
- True file-based routing with no `app/` vs `pages/` ambiguity
- Nitro engine means the same codebase deploys to Node, serverless, or edge workers without config changes
- React 19 Server Components mean the AI blueprint generator runs SSR with zero client JS
- Router-first approach is more predictable than Next.js conventions

Trade-off: smaller ecosystem and fewer tutorials. Worth it for the DX.

---

**Database schema highlights**:

The Supabase schema has some interesting patterns:
- `user_secrets` table with RLS + encryption at rest
- `project_blueprints` stores the full AI-generated schema as JSONB with versioning
- Edge functions for Stripe webhook idempotency (the hardest part to get right)
- Row-level security policies that cascade from org → project → environment

---

**Performance numbers** (Cloudflare Workers edge):
- Lighthouse: 98 Performance, 100 Accessibility
- First paint: ~180ms (global edge)
- AI blueprint generation: 2-4s (includes Claude 3.5 Sonnet call)
- SSR cold start: ~50ms on Workers
```
