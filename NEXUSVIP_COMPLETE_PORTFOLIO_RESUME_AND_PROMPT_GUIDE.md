## 🎤 7. Technical Interview Defense & Architecture Cheat Sheet

#### 💡 Q1: "What was the most challenging technical problem in this project?"
> *"The multi-runner liability calculation and atomic balance locking. In a betting exchange, laying multiple runners in the same market creates opposing exposure where only one outcome can lose. I designed an algorithm that calculates the worst-case scenario across all outcomes and locks only the net required liability rather than raw sum of stakes, maximizing player capital efficiency while guaranteeing platform solvency."*

#### 💡 Q2: "How did you design the authentication and Telegram bot delivery?"
> *"I engineered a multi-gateway verification engine prioritizing Telegram Bot API (`@nexusvip_verify_bot`). On dispatch, the frontend launches the native Telegram client with a session-bound start parameter (`/start otp_<hash>`). When the user taps START, the long-polling backend catches the event, extracts their chat identity, pushes the 6-digit OTP, and maps their account for future push notifications, achieving zero-cost, high-reliability delivery."*

#### 💡 Q3: "How do you guarantee that concurrent bets do not double-spend wallet balance?"
> *"I implemented atomic transaction locks on the user credit ledger. Before any bet is accepted into the order matching engine, the available balance is verified and locked within an isolated transaction scope. If two requests arrive simultaneously, the second transaction is evaluated strictly against the residual uncommitted credit, preventing overdraft or double-spend exploits."*
